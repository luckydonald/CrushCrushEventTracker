## Compact-result file naming

Both 008 and 009 share the session UUID `b8d65089-1cc7-406f-aa17-4d93574e41cc`, folder pattern `ai/output/compact/<seq>.<uuid>/result.md`.
Two shapes exist for the same kind of file: `<analysis>`/`<summary>`-tagged ("summary" shape, seen on 009) and plain untagged ("resume" shape, seen on 008).

### "summary" shape (009) — structure only, content redacted

Whole file wrapped in two top-level tags, no prose outside them:

```
<analysis>
...
</analysis>

<summary>
...
</summary>
```

**`<analysis>` block** — free-form prose, numbered list 1-8, chronological walkthrough of the session leading to this compact:

1. What session was resumed from (prior compact).
2. What got done since (commits, decisions), narrated step by step.
3. Enumerated sub-items (a-z / bullet) per work item, each naming files touched + commit hash.
4. Notable "gotcha" encountered mid-session (here: a background task's misleading "exit code 0" framing).
5. Detailed dump of the actual failing/erroring output (stack traces, panic messages, error codes) that triggered this compact.
6. Cross-reference to prior memory/session notes, noting whether they're stale.
7. Explicit "what I have NOT done yet" disclaimer — guardrail against hallucinating completed work.
8. "Key files I'll need to look at next" bullet list with file paths, justified from context, each flagged not-yet-read.

Closing line: explicit tool-call constraint for this turn + confirmation next turn starts the real work.

**`<summary>` block** — same 9 fixed section headers every time (numbered, bold-titled):

1. **Primary Request and Intent** — original ask + most current live instruction, verbatim-quoted.
2. **Key Technical Concepts** — bullet list of stack/framework/pattern names relevant to resuming.
3. **Files and Code Sections** — bullet list, one per file, each with a "not yet read/edited this segment" flag.
4. **Errors and fixes** — split into already-resolved (brief) vs. currently-unresolved (detailed, this is the pending task).
5. **Problem Solving** — ongoing hypotheses / open questions blocking the fix.
6. **All user messages** — verbatim list, non-tool-result turns only, this segment.
7. **Pending Tasks** — bullet list, explicit scope boundary quoted from user.
8. **Current Work** — narrative of the immediate last few actions before this compact fired.
9. **Optional Next Step** — one paragraph, ties directly back to section 1's live instruction.

Trailing pointer line to the full transcript path is NOT part of this tagged shape (only in the "resume" shape below).

### "resume" shape (008) — structure only, content redacted

Plain markdown, no `<analysis>`/`<summary>` tags — just a leading disclaimer line, then the same 9 fixed numbered sections as above, un-tagged:

```
This session is being continued from a previous conversation that ran out of context. The summary below covers the earlier portion of the conversation.

Summary:
1. Primary Request and Intent:
2. Key Technical Concepts:
3. Files and Code Sections:
4. Errors and fixes:
5. Problem Solving:
6. All user messages (verbatim, non-tool-result turns only):
7. Pending Tasks:
8. Current Work:
9. Optional Next Step:
```

Differences vs. the "summary" shape:
- No `<analysis>` walkthrough section preceding it — starts straight at the numbered summary.
- Ends with two trailing instruction lines not present in the "summary" shape:
  - a pointer to the full raw transcript path (`/home/user/.claude/projects/<slug>/<uuid>.jsonl`) for recovering exact snippets,
  - an explicit "continue directly, no recap, no acknowledgement" directive for the next turn.

## Where the two hook paths cross

- `PreCompact` writes `001.md`/query.md link via `save-compact-prompt/hook.py`'s non-`PostCompact` branch, keyed to its own `output/compacted/NNN.md` counter — no shared key with `output/compact/NNN.<uuid>/` beyond `prompt_id`, which never surfaces in that block's rendered markdown.
- `PostCompact` and `SessionStart(source=compact)` both end up in `compact_result.capture_summary()` for the same `prompt_id`, but with different content ("summary" vs "resume" shape) — `reserve_artifact_directory()` only reuses a directory when it finds byte-identical content for a given `prompt_id`; since these two shapes never match, the second caller falls through to `next_compact_number()` and gets a new directory (`009`) instead of adding a second artifact next to `008`.
- Every one of these git-writing call sites (`save-compact-prompt/hook.py`'s manual-instructions branch, `compact_result.capture_summary()`) shells out via `subprocess.run(["git", "commit", ...], capture_output=True)` and never inspects `returncode` — `008`'s commit silently failed (left staged) with no error surfaced anywhere.
