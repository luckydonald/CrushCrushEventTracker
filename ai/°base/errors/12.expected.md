>> How should errors be surfaced to the caller?
> - [ ] 1\. Exceptions (Recommended)
>   - _Raise typed exceptions; caller uses try/except._
>   - ```
>     class NotFoundError(AppError):
>         pass
>
>     def get_user(uid: int) -> User:
>         if not found:
>             raise NotFoundError(uid)
>     ```
> - [ ] 2\. Result type
>   - _Return Ok/Err wrapper; caller pattern-matches._
>   - ```
>     def get_user(uid: int) -> Result[User, str]:
>         if not found:
>             return Err(f"user {uid} not found")
>         return Ok(user)
>     ```
> - [ ] 3\. Optional + logging
>   - _Return None on failure and log internally._
>   - ```text
>     def get_user(uid: int) -> User | None:
>         if not found:
>             logger.warning("user %s not found", uid)
>             return None
>         return user
>     ```

# Notes
- Pretty much every question had an "other" kind-of field:
  - If a custom answer is given, use `Type something:`, otherwise use `Type something.`.
    - For a multi-select all entries are added by ` ,`, but may not be in order of the list, but in order of the user selecting it.
    - So far the custom one is always last (?)
  - If using a `preview` field, the custom answer will be `Notes:` vs. `Notes: _Add notes on this design…_` instead of `Type something…`.
    - You need to handle the `(notes only)` special case, where then the "answer" will be in `annotations[question].notes`.
